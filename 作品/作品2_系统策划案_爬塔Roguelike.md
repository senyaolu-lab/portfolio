## 1. 设计概述

### 1.1 一句话定位
一款**每局 15 分钟、单手竖屏操作**的 Roguelike 爬塔游戏：玩家在随机生成的回廊中战斗、捡遗物、凑流派，爬得越高奖励越强。

### 1.2 背景与动机
- **问题**：市面主流 Roguelike（杀戮尖塔/哈迪斯）单局 30 分钟以上、操作密度高，无法覆盖通勤与碎片场景；
- **机会**：竖屏 + 单手 + 15 分钟单局 = 移动端空白的"轻量 Roguelike"生态位；
- **目标**：用"流派构筑的意外惊喜"（玩家捡到两个遗物后惊呼"原来还能这么玩"）作为核心体验，驱动复玩。

### 1.3 目标用户
18-35 岁、玩过但被"重度 Roguelike"劝退的休闲-中度玩家；每日游戏时间碎片化。

### 1.4 功能范围（MVP 边界）
- **本期实现**：随机地图生成、自动战斗+1 个主动技能、遗物三选一、金币商店、诅咒机制、Boss 房、局外微成长（初始遗物槽）；
- **本期不实现**：多角色（预留）、装备掉落、排行榜、联机；PvP 与赛季为长期规划。
- **扩展预留**：遗物表预留 `combo_group` 字段（见 6.2），支持未来套装效果。

### 1.5 对标产品
《杀戮尖塔》（构筑深度）×《吸血鬼幸存者》（自动战斗与成长反馈）× 竖屏单手操作。

## 2. 核心循环

进入楼层 → 选择房间（战斗房 / 事件房 / 商店 / 诅咒房）。战斗房：自动战斗与主动技能，胜利后三选一奖励（遗物 / 金币 / 治疗）；事件房：事件抉择；商店：购买遗物或刷新；诅咒房：高风险诅咒换强力收益。集齐进度后挑战楼层 Boss，击败后进入下一层，如此循环；战斗中死亡则进入结算（局外微成长与图鉴解锁），随后再来一局。

## 3. 系统拆解

### 3.1 地图与房间生成
- 每层地图为 3×4 房间网格的**随机连通子集**，入口在左下、Boss 房在右上；
- 房间类型权重（随层数变化）：战斗 55% / 事件 15% / 商店 10% / 诅咒 8% / 精英 12%；
- 生成规则：商店与诅咒房**不与入口相邻**；精英房必为战斗房变体，奖励+1 选。

### 3.2 战斗系统（引用《作品3_数值设计》公式）
- 角色**自动普攻**，玩家操作仅：移动（拖拽）+ 1 个主动技能（点击，CD 8-15 秒按构筑缩减）+ 走位；
- 伤害公式：`Damage = ATK × 技能系数 × (1 + 增伤%) × [ATK / (ATK + DEF)]`，详见作品 3 第 2 章；
- 战斗时长目标：普通房 20-40 秒、精英 60-90 秒、Boss 120-180 秒。

### 3.3 遗物系统（构筑核心）
- 掉落：战斗房胜利后**三选一**（稀有度权重：普通 60% / 稀有 30% / 传说 10%），精英房提升稀有概率 2 倍；
- 稀有度效果强度基准：普通=+10% 数值 / 稀有=机制改变 / 传说=流派核心；
- **流派组合规则**：遗物带 `element` 与 `combo_group` 标签；集齐同组 3 件触发组合效果（例：火焰三件套→灼烧层数翻倍）；
- 上限：遗物槽 8 格，满后可替换不可叠加（同名遗物允许重复持有，效果线性叠加）。

### 3.4 事件系统
- 事件表条目 20+，结构：`触发条件 → 选项（1-3个）→ 结果（获得/失去/战斗）→ 隐藏条件`；
- 设计原则：每个事件至少一个选项**有代价**（付出生命/金币/遗物换收益），保证"抉择感"。

### 3.5 商店系统
- 货币：金币（局内产出，局内消费，不跨局）；
- 商店固定 3 件商品 + 刷新（首次 20 金，每次翻倍，上限 3 次）；
- 定价锚点：普通遗物 60-90 金 / 治疗 25 金（30% 生命）/ 刷新成本递增设计，见作品 3 第 4 章经济模型。

### 3.6 诅咒系统（风险构筑）
- 诅咒房提供 3 选 1"高风险诅咒"（如"怪+30% 血量，金币+50%"），可**主动进入**；普通战斗奖励偶尔附带低风险诅咒；
- 设计意图：解决 Roguelike 后期"build 固化、站桩无聊"问题，用风险换构筑上限（呼应作品 1 的增量设计）。

### 3.7 结算与局外成长
- 死亡/通关结算：展示本局遗物组合、伤害构成、层数；
- 局外成长**克制**：仅解锁"初始遗物槽"（最多 2 个）与图鉴，不做数值膨胀——保护 Roguelike 的"每局公平"。

## 4. 关键规则与边界 Case（节选 12 条中的 6 条）

| # | 场景 | 规则 |
|---|---|---|
| 1 | 遗物槽已满时三选一 | 可替换：选择后弹二次确认"替换 X 遗物" |
| 2 | 商店刷新时金币不足 | 刷新按钮置灰并显示差额，不弹窗打断 |
| 3 | 战斗中断网/切后台 | 单机局内：战斗暂停，回前台可继续；断线重连由服务端存局快照（联机版本） |
| 4 | 三选一界面切后台 | 奖励在进入界面瞬间已确定并落库，重进不重roll |
| 5 | 连续快速点击主动技能 | 按钮按下即置灰进 CD，防连点（服务端校验 CD） |
| 6 | 同组遗物 3 件时组合触发 | 触发瞬间结算一次组合效果并播特效，替换掉同组遗物时组合效果同步回收 |

## 5. 界面布局

- 顶部栏：当前层数、暂停与设置入口；
- 状态区：生命条与金币余额；
- 战场区：自动战斗的俯视场景，玩家拖拽移动；
- 底部：主动技能按钮（图标与冷却倒计时）；
- 进度区：当前波次进度条。

## 6. 配置表设计

### 6.1 遗物表 `relic_config`

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| relic_id | int | 是 | 唯一 ID | 1001 |
| name | string | 是 | 名称 | 余烬火种 |
| rarity | int | 是 | 1 普通/2 稀有/3 传说 | 2 |
| element | int | 否 | 0 无/1 火/2 冰/3 雷（默认 0） | 1 |
| combo_group | int | 否 | 组合组 ID（默认 0） | 101 |
| effect_type | int | 是 | 效果类型枚举 | 3 |
| effect_param | float | 是 | 效果参数 | 0.3 |
| desc | string | 是 | 描述文案（含占位符 {p}） | 灼烧伤害 +{p}% |
| is_active | int | 是 | 1 启用 / 0 停用 | 1 |

> 协作约定：`effect_type` 枚举由程序维护映射表；`{p}` 由客户端替换为 `effect_param`；策划只改表，不改代码。

### 6.2 其他表清单
`skill_config`（主动技能）、`monster_config`（怪物属性/波次）、`event_config`（事件/选项/结果）、`room_config`（房间权重）、`shop_config`（商品池/刷新成本）。

## 7. 数值框架（详见作品 3）

| 项 | 参数 | 设计目标 |
|---|---|---|
| 角色成长 | ATK = 50 × 1.08^(层数-1) | 每层 +8% 强度 |
| 怪物血量 | HP = 40 × 层数^1.2 | 击杀时长稳定在 3-8 秒 |
| 商店定价 | 遗物 60-90 金 | 每层金币盈余 ≈ 1 件商品，制造"取舍" |
| 主动技能 CD | 8s 基础，构筑可缩至 4s | 决策频率：每 8 秒一次主动决策 |

## 8. 埋点与验证

| 假设 | 验证指标 | 阈值（不达标则改） |
|---|---|---|
| 15 分钟单局符合碎片场景 | 局均时长分布 | 50% 局落在 12-18 分钟 |
| 流派构筑有惊喜感 | 同层遗物组合多样性（香农熵） | ≥ 3.5 bits |
| 诅咒系统拉动复玩 | 选诅咒玩家次日留存 | 高于未选组 5pp |
| 死亡挫败感可控 | 死亡后 10 分钟内再开率 | ≥ 40% |
| 商店刷新有博弈 | 每局刷新次数分布 | 中位数 1-2 次 |

## 9. 里程碑与风险

| 里程碑 | 内容 | 风险与预案 |
|---|---|---|
| M1（第 4 周） | 白盒原型：房间生成+战斗 | 手感差→先保"成长爽感"再调战斗 |
